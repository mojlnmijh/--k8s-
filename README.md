# 闪学it-马士兵-k8s应用架构师（云原生）
获课：shanxueit.com/14353/马士兵-k8s应用架构师（云原生）


云原生进阶必修课，马士兵 K8s 应用架构师课程解读
云原生走到今天，K8s 早已不是“会用 kubectl 就算入门”的阶段。企业真正缺的，是能从架构层面设计、治理和优化容器平台的人。会部署一个 Deployment 和能设计一套多集群、可观测、可弹性的应用架构，中间隔着大量实战经验。马士兵这套 K8s 应用架构师课程，定位正是填上这道鸿沟。它不是入门教程的加长版，而是面向“进阶”重新组织知识体系，把 K8s 从工具层面拉到架构层面来讲。

课程首先解决的是“知识碎片化”问题。 很多人学 K8s 的路径是遇到问题查文档：Pod 起不来查调度，服务不通查网络，性能不够查资源限制。零散解决过不少故障，但脑子里没有一张完整的架构图。这套课程的做法是先建立全局视角：集群由哪些核心组件构成，控制面和数据面各自负责什么，一次请求从入口到 Pod 要经过哪些环节。有了这条主线，再去看调度、网络、存储、安全，每个模块都能找到自己的位置。进阶学习最怕的就是“每个点都懂，连起来就懵”，课程用架构主线把点串成了面。

第二个重点是工作负载与调度策略的深度。 入门课通常只讲 Deployment 和 Service，但真实生产环境远不止这些。什么时候用 StatefulSet，什么时候用 DaemonSet，Job 和 CronJob 的失败重试怎么设计，HPA 和集群自动扩缩容如何配合，亲和性与反亲和性怎么影响可用性。课程没有停留在“是什么”，而是结合场景讲“为什么选它、代价是什么”。比如节点亲和性能提升性能，但可能降低调度灵活性；Pod 反亲和性提高容错，但会增加资源碎片。架构师的价值不在于记住参数，而在于能说清权衡。

第三个板块是网络与流量治理。 K8s 网络是进阶路上绕不开的硬骨头。Service 的几种类型、Ingress 与 Gateway API 的差异、CNI 插件的基本原理、NetworkPolicy 的隔离逻辑，这些内容课程做了系统梳理。更实用的是流量治理部分：灰度发布、金丝雀、熔断限流、服务网格的引入时机。很多团队上了 K8s 之后发现发布仍然靠停机，问题就出在流量层没有设计好。课程把网络讲成“流量怎么进来、怎么分发、怎么保护、怎么观测”的完整链路，而不是孤立地讲某个资源对象。

第四个板块是可观测性与稳定性。 应用上了 K8s，出问题时排查难度反而更大：是应用挂了、节点异常、网络抖动还是调度失败？课程把日志、指标、追踪三条线讲清楚，并强调告警设计要围绕 SLO 而不是堆指标。稳定性部分涉及探针配置、PDB、多副本与多可用区、备份恢复和故障演练。架构师不仅要让系统跑起来，还要让系统在部分组件失效时仍然可用。这部分内容对从开发转架构的人尤其重要，因为它训练的是“故障视角”。

第五个板块是安全与多租户。 RBAC 权限模型、ServiceAccount、镜像安全、Secret 管理、命名空间隔离、准入控制，这些在企业落地时全是必答题。课程没有把安全讲成吓人的合规清单，而是结合多团队共用集群的真实场景，讲清楚权限边界怎么划、资源配额怎么设、审计怎么做。对想往平台架构方向走的人来说，这块能力直接决定能不能扛住生产环境。

最后是架构案例与落地方法。 课程用贴近生产的场景串联前面所有模块，强调从需求到架构的推导过程：业务有什么特征，容量怎么估算，可用性目标定多少，再反推集群设计和资源规划。这种训练比背命令有用得多，因为面试和实际工作问的都是“你为什么这样设计”。

整体来看，这套课程适合已经会用 K8s 基本操作、想往应用架构师或平台工程师方向进阶的人。它不承诺速成，但知识体系完整、场景感强、强调权衡思维。云原生进阶的必修课，不是学更多命令，而是学会像架构师一样思考：在约束中做选择，在故障中保底线，在演进中留余地。
